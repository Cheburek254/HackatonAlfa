# Сравнение бейзлайна и `recommend`

Оба набора запускаются независимо из корня проекта или из раздела «Тесты рекомендаций» в админ-панели.

```bash
python -X utf8 -m evaluation --suite demo
python -X utf8 -m evaluation --suite real
python -X utf8 -m evaluation --suite real --catalog data/catalog_slim.sqlite
```

Каждый запуск прогоняет `recommend_by_topic` и `recommend` на одном каталоге, профилях и журнале событий. В обоих вызовах `limit=3`. Отчёт выводится в stdout в Markdown. Первая таблица содержит итоговые Hit@3 и MRR@3, вторая показывает выданные ID и баллы по каждому профилю.

Офлайн-прогон работает без внешней модели для пояснений и без записи событий в базу пользователей. Для реального набора используются связи из `recommended_links.json` рядом с файлом каталога, если файл доступен. При отсутствии экспорта или размеченных ID реальные тесты сообщают об ошибке.

`recommend_by_topic` использует общий контракт `Recommender`. Он ищет темы каталога как целые слова или фразы в тексте задачи. Перед сравнением нормализует регистр, разбивает текст по пунктуации и заменяет «ё» на «е». Материалы с большим числом совпавших тем идут первыми, при равенстве сохраняется порядок каталога. Пустая задача и запрос без совпадений дают пустую выдачу. Стадия, сфера, опыт и история предназначены для проверки персонализированного алгоритма.

`profiles.demo.json` содержит 50 размеченных сценариев для общего каталога из `fixtures/catalog.demo.json` и `catalog.extra.json`. В каждом сценарии `profile` задаёт вход, `relevant_ids` перечисляет подходящие материалы, а `note` объясняет разметку. Поле `history_fixture` подключает журнал из `fixtures/`. Сценарии проверяют в том числе историю, ограничения по цене, юридическую форму и отраслевую лексику.

`profiles.real.json` содержит 350 авторских сценариев с релевантными ID из серверного экспорта «Альфа-Курса». Первые 100 сценариев сохранены, следующие 250 распределены по 25 группам задач. Разметка опирается на содержание, формат и доступность материала. Задачи охватывают запуск бизнеса, налоги, финансы, продвижение, маркетплейсы, команду, документы, операционную работу, закупки и технологии. События `history` заданы для сценария и ссылаются на реальные материалы. Список релевантных карточек в каждом сценарии служит проверяемым эталоном и может быть дополнен после экспертной проверки.

- **Hit@3** — доля сценариев, где в первых трёх рекомендациях появился хотя бы один материал из `relevant_ids`.
- **RR@3** для одного сценария равен `1 / позиция` первого релевантного материала в топ-3. При промахе он равен нулю. **MRR@3** — среднее этих значений.

Сценарии с пустым `relevant_ids`, например `outside-catalog`, видны в таблице и исключаются из знаменателя обеих метрик. Так ответ на запрос за пределами каталога можно проверить по выданным ID отдельно.

## Качество рекомендаций и каталога

Отчёт строится офлайн для действующего `recommend` и показывается в админке. Запустите команды локально с исходным бэкапом и тем же экспортом, который использует сайт.

```bash
python -m pip install numpy==2.2.6
python -m evaluation.catalog_quality --backup /path/to/alfa_course_hackathon.backup --catalog data/catalog_slim.sqlite --output data/catalog-quality.json
```

Скопируйте только `catalog-quality.json` в папку экспорта на сервере. В отчёте хранятся агрегаты и названия карточек холодного старта. Бэкап и данные отдельных пользователей остаются на машине, где запускался расчёт. Админка сверяет отпечаток каталога перед показом отчёта.

- Покрытие, Джини и разнообразие считаются по выдачам 350 размеченных запросов. Покрытие материалов без событий использует доступные журналы активности, а текстовые векторы строятся из заголовков, описаний, тегов и блоков статей и уроков.
- Для истории берётся воспроизводимая выборка из 300 пользователей. События на последней временной отметке исключаются. Оцениваются повтор завершённого курса или урока, совпадение тем с оценками 4–5 и платная выдача для пользователя с условно бесплатным доступом. Для проверки персональных прав нужна отдельная выгрузка назначений подписок.
- Холодный старт проверяется на шести профилях без истории. Для пустого профиля проверяется точный состав онбординг-пакета. Для заполненных профилей проверяются бесплатные вводные курсы и популярные статьи. Экспертное совпадение считается по направленным связям из бэкапа с отключённым графом в ранжировщике.

## Специализированные офлайн-проверки

```bash
python -m evaluation.stress --backup /path/to/alfa_course_hackathon.backup --catalog data/catalog_slim.sqlite --output data/recommendation-stress.json
```

Команда сравнивает `recommend`, BM25 и гибрид на прежних 400 сценариях и пяти новых наборах по 50. Временная проверка скрывает последнее или предпоследнее однозначное событие с новым курсом и строит кандидатов и индекс BM25 по материалам, опубликованным раньше. Для неё исключены текущие баллы популярности, рейтинги и экспертный граф. Метаданные берутся из снимка каталога.

Другие наборы проверяют совпадение с негативным фидбеком, смену контекста, редкие форматы и отрасли, три состояния холодного старта. Смена контекста моделируется на реальных материалах. Низкие оценки и малый прогресс считаются отдельно. Пустые выдачи отдельно отражены в проверке негатива.

Дополнительные 50 проверок экспертного графа используют разбиение пар 80/20. Обратные рёбра остаются в той же части. Для ловушек берутся статьи без общей разметки и без прямой связи с источником. Если в экспорте отсутствует измеренная популярность статей, при отборе используется число входящих рёбер открытой части графа.

В старых сценариях BM25 использует только текст задачи. В новых при отсутствии текста запроса он также может использовать отрасль, тему и названия двух последних материалов. Гибрид объединяет обратные ранги с одинаковыми весами и применяет явно указанные ограничения формата, доступа и цены. Оба алгоритма запускаются офлайн.

В папку экспорта сайта можно скопировать только `recommendation-stress.json`. Он содержит агрегаты и показывается в админке после сверки отпечатка каталога. Проверка двух вариантов доступа к Курс+ запускается при открытии админки и использует те же данные о подписке, что и карточки.

## Сложные учебные сценарии

```bash
python -m evaluation.learning --backup /path/to/alfa_course_hackathon.backup --catalog data/catalog_slim.sqlite --output data/learning-evaluation.json
```

Офлайн-команда использует NumPy для TF-IDF и SVD. Админка показывает пять новых наборов по 50 сценариев, сравнение трёх методов, разбивку по группам и один пример смоделированной истории на набор. Предыдущие отчёты работают отдельно.

- **Прогрессия** сочетает 30 историй новичков и 20 сценариев после завершения всех уроков. Используются подтверждённые события завершения и смоделированный дополнительный контекст. Уровни сложности — оценка по метаданным и ручным правилам. Доля продвинутых считается только среди карточек с размеченным уровнем. Покрытие уровня выводится отдельно.
- **Теория → инструмент** проверяет размеченные калькуляторы и шаблоны на 50 разных задачах, по пять на тему. У профилей одновременно есть несколько интересов, недавние чтения по основной теме и постороннее событие.
- **Устойчивость к шуму** сравнивает неизменный запрос и три версии истории. Один мисклик должен сохранить две релевантные карточки из исходного топа. После двух или трёх действий по другой теме проверяется появление двух карточек по новой теме. Отдельно показана устойчивость среди выдач, которые были релевантны до вмешательства.
- **Дубли** проверяются на парах из плотных областей каталога. Нарушение — сходство строго выше 0,85 хотя бы у одной пары в полном топ-3. Векторы представляют заголовки, описания и текстовые блоки, включая глоссарий. Похожие материалы могут быть отдельными полезными версиями одного документа, поэтому порог используется как диагностическая метрика.
- **Свежесть** сопоставляет карточку с более старым материалом того же формата и общей темы. В половине проверок цель взята из последних 12,5% датированных публикаций, в другой — у эксперта с поздним первым появлением и малым числом оценок. Контрфактуал убирает текущие оценки и популярность у всех кандидатов. Это проверка сигнала популярности, а не имитация нового коэффициента свежести.

На сервер передаётся агрегат `learning-evaluation.json`. Реальные истории отдельных пользователей и идентификаторы авторов в нём отсутствуют.

## Программы курсов

Свежая сборка каталога добавляет уроки и их связи с курсами в SQLite. Для существующего экспорта можно обновить только эти таблицы, сохранив материалы и порядок экспорта.

```bash
python -m app.catalog.lessons --backup /path/to/alfa_course_hackathon.backup --catalog data/catalog_slim.sqlite
```

Представление `standalone_lessons` содержит активные уроки без связи с любым курсом. Привязки к черновым или архивным курсам тоже учитываются. Программа опубликованного курса показывает названия, модули, типы и пометки о пробных уроках.
