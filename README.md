# Альфа-Курс — персональные рекомендации

Прототип для трека 1. Веб-страница и консоль используют `app.recommender.recommend` для подбора по задаче, профилю и истории.

## Быстрый запуск

Запуск в Docker Compose из корня проекта:

```bash
docker compose up --build -d --wait
```

Демо доступно на [127.0.0.1:18081](http://127.0.0.1:18081/). Через «Профиль» можно создать аккаунт, войти по паролю или открыть общий тестовый профиль. При регистрации нужно выбрать стадию, сферу, опыт, размер команды, тему и формат обучения. Настройки тестового профиля заданы заранее и доступны для просмотра.

## Развёртывание на сервере

Разверните `main` в отдельном каталоге сервера. Compose использует имя проекта `alfahack-demo` и внутренний порт `8080`. Для настройки скопируйте `env.example` в `.env`. По умолчанию сервис слушает `127.0.0.1:18081`. Для доступа по домену направьте reverse proxy на этот адрес. Для прямого доступа по IP задайте `APP_BIND_ADDRESS=0.0.0.0` и откройте выбранный `APP_PUBLIC_PORT` в настройках сервера.

```bash
docker compose config --quiet
docker compose up --build -d --wait --wait-timeout 90
docker compose ps
curl --fail http://127.0.0.1:18081/health
```

Положите экспорт каталога в `data/` или укажите путь к каталогу на хосте в `ALFA_CATALOG_DIR`. Compose монтирует эту папку только для чтения. Приложение берёт первый доступный файл в порядке `catalog_slim.sqlite`, `catalog_slim.json`, `catalog.norm.json`. Если есть `recommended_links.json`, положите его рядом, чтобы ранжирование учитывало связанные материалы. После обновления выгрузки перезапустите сервис `web`.

Если в `data/` есть только исходный `alfa_course_hackathon.backup`, экспорт можно собрать командой `python -X utf8 -m app.catalog.normalizer`. Для веб-демо достаточно нормализованного каталога и файла связей. Исходный бэкап остаётся вне Git и Docker-образа.

С отдельными путями используйте `python -X utf8 -m app.catalog.normalizer --backup path/to/alfa_course_hackathon.backup --output data/new-catalog`.

Без экспорта и без заданного `ALFA_CATALOG_DIR` используется каталог из `fixtures/`. При явно заданном `ALFA_CATALOG_DIR` приложение требует доступный экспорт. `/health` сообщает `catalog: real` или `catalog: demo` и число загруженных материалов.

Бесплатные статьи с обязательным входом входят в фильтр «Бесплатные». Каталог показывает карточки всех выбранных категорий и ведёт на Альфа-Курс, где проверяются права пользователя. Для отчётов в `/admin/tests` положите экспорт, направленные редакторские связи и JSON-прогоны по той же версии каталога в папку `ALFA_CATALOG_DIR`.

Для входа и регистрации по публичному адресу настройте HTTPS. За reverse proxy оставьте порт приложения доступным прокси и настройте в Waitress `trusted_proxy` на его адрес, а в `trusted_proxy_headers` явно разрешите `X-Forwarded-Proto` и `X-Forwarded-For`. Для публичного HTTP доступна кнопка тестового входа.

На сервере с уже настроенным обновлением сертификатов Let’s Encrypt используйте отдельный прокси. В `.env` задайте `ALFA_HTTPS_HOST` из сертификата и `ALFA_CERT_ROOT` с каталогами `live/` и `archive/`. Запустите `docker compose -f compose.yaml -f deploy/compose.https.yaml up --build -d --wait`. HTTPS по умолчанию использует порт `18443`. Старый HTTP-порт перенаправляет на него. Прокси перечитывает сертификат после обновления.

Аккаунты сохраняются в SQLite в томе `accounts`. Сделайте резервную копию тома перед переносом на другой сервер. В серверном `.env` задайте постоянный случайный `ALFA_SECRET_KEY`, например сгенерируйте его командой `python -c "import secrets; print(secrets.token_hex(32))"`. С постоянным ключом сессии сохраняются при перезапуске контейнера.

## Запуск без Docker

Из корня репозитория с Python 3.12.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m waitress --listen=127.0.0.1:18081 --call app.ui.web:create_app
```

Откройте [веб-демо](http://127.0.0.1:18081/). Поле задачи и профиль необязательны. После входа в личный аккаунт открытие карточки сохраняет просмотр, а кнопка «Открыть на сайте» сохраняет переход. События хранятся в SQLite. Для подбора передаются до 100 последних сочетаний материала и действия за 90 дней. На синтетическом каталоге гостям и общему тестовому аккаунту доступен пример истории. Кнопка «Пропустить» запускает подбор без параметров и истории на один запрос.

Веб-выдача показывает карточки из `recommend` постранично — по `6`, `12` или `24` карточки на странице (с переключателями страниц и скрытием кнопок «Назад»/«Далее» на граничных страницах). Режимы «По популярности» и «По оценке» сортируют подборку по убыванию и пропускают материалы без выбранного показателя. Из экспорта берутся `popularity_score`, `recent_popularity_score`, `avg_rating` и `cost`, когда они доступны. JSON также принимает поля `popularity`, `recent_popularity` и `rating`. Показатели в тестовой фикстуре синтетические.

В общем режиме позиции 4–6 учитывают баланс доступа. Новичку система стремится показать один подходящий платный или подписочный вариант, опытному профилю с историей — до трёх на первые шесть. Переставляются только близкие по оценке варианты. Галочки доступа, фильтр формата, ручная сортировка и ограничения бюджета из запроса имеют приоритет. Состав первых шести виден над карточками. После бесплатного материала отдельная страница может предложить один платный курс по совпадающей теме, с явной пометкой доступа и переходом на Альфа-Курс.

Перед поиском главная показывает до пяти статей и пяти подкастов в одной горизонтальной ленте. Подбор учитывает темы истории во всех форматах, параметры профиля и даты публикации. Без подтверждённых интересов и заполненного профиля приоритет получают доступные вводные материалы по разным темам. Файл `publication-dates.json` строится из дат опубликованных статей и подкастов при экспорте каталога. Для существующего экспорта его можно подготовить отдельно командой `python -m app.catalog.publications --backup path/to/alfa_course_hackathon.backup --catalog data/catalog_slim.sqlite --output data/publication-dates.json`.

Под хиро-блоком на главной отображается отдельная карусель **«Следующий курс»** (`app.recommender.next_courses`). Она показывает до шести доступных пользователю курсов, с которыми ещё не было взаимодействий в истории, и сортирует их по недавней популярности (`recent_popularity_score`, рассчитываемой при нормализации по датам стартов и завершений в `CourseUserBindings` с периодом полураспада 45 дней).

На `/admin` администратор может выбрать режим каталога. По умолчанию используется адаптивный гибрид BM25 и `recommend` с базовыми весами 25% и 75%. Для конкретного запроса доля BM25 может вырасти до 74,9%. Для новичков и перехода от теории к инструменту остаётся базовая пропорция. Базовую долю BM25 можно задать через `ALFA_BM25_WEIGHT`. Новые A/B-тесты используют адаптивный гибрид, а прежние сохраняют записанную фиксированную долю. Выбор режима хранится в SQLite, а показы каталога привязываются к алгоритму, который сформировал карточки. Бейзлайн строит общий топ курсов по популярности с учётом выбранных в каталоге фильтров. Сохранённые офлайн-прогоны доступны на `/admin/tests`.

### Поиск в чате

Чат ведёт свой поиск среди материалов, доступных пользователю. Он использует адаптивный гибрид с отдельным базовым весом `ALFA_CHAT_BM25_WEIGHT` (по умолчанию `0.25`). Смена режима каталога и его A/B-тесты не переключают чат. Справка о профиле, Курс+ и сбоях, уточнение непонятного запроса и выбор карточки по номеру обрабатываются локально.

`POST /api/chat` принимает `message`, до шести прошлых реплик в `history` и необязательный `card_context` из последнего ответа. Ответ содержит `reply`, упорядоченный список `cards`, `source`, `intent` и подписанный контекст карточек. Виджет хранит контекст во вкладке до сброса чата. Доступ к каждой карточке проверяется при повторном запросе, срок подписи составляет сутки. Подписанный `click_context` передаётся в `POST /api/chat/card-open` при открытии карточки.

Gemini и OpenRouter делят бюджет ожидания в восемь секунд. При сбое чат отдаёт карточки из каталога. Лимиты составляют 16 сообщений в минуту на аккаунт или гостевую сессию и 120 обращений к моделям в минуту на приложение. Страница `/admin/analytics` показывает p95 времени ответа, долю резервных ответов на подбор и открытия карточек за 30 дней. Для этой статистики сохраняются время, тип и источник ответа и факт открытия. Текст диалога в статистику не записывается.

Без Docker база создаётся в `data/accounts/users.sqlite3`. Путь можно задать через `ALFA_DATABASE_PATH`.

Таблица `recommendation_impressions` хранит ID карточки, позицию после сортировки, алгоритм, тип сортировки, аудиторию и время показа и перехода в UTC (Unix-секунды). Показ засчитывается, когда в область просмотра активной вкладки попала хотя бы половина карточки. Переход к материалу также подтверждает показ. Повторное появление той же карточки на той же позиции при перелистывании страниц учитывается один раз. Идентификатор алгоритма берётся из имени функции, а для различения версий можно передать `algorithm_name` в `create_app`.

### Как устроен алгоритм рекомендаций

Ядро подбора (`app.recommender.recommend` в режиме адаптивного гибрида с BM25) объединяет контентное соответствие, поведенческую историю и контроль разнообразия:

1. **Текстовый и смысловой поиск (включая шаблоны и калькуляторы):** запрос пользователя и параметры профиля (стадия, отрасль, опыт, тема, формат) сопоставляются с заголовками, описаниями, темами и встроенным текстом страниц шаблонов (`DocumentEmbedItems` → `search_text` с ограничением веса, чтобы длинные шаблоны не размывали общие запросы). Для запросов про документы, бланки, шаблоны, калькуляторы и расчёты дополнительно повышается вес соответствующего формата.
2. **Адаптивный гибрид BM25 + `recommend`:** по умолчанию используется адаптивное смешивание лексического BM25 (базовый вес `0.25`) и контентно-поведенческого скоринга `recommend` (`0.75`); при точных предметных запросах доля BM25 автоматически усиливается до `74,9%`.
3. **Реакция на историю и защита от случайных кликов (`recommend:history-v3.1`):** тема подтверждается двумя переходами к **разным** материалам за последние 14 дней с совпадением по достаточно редким темам или словам заголовка. При расплывчатом запросе до двух первых позиций отводятся продолжению этой темы. Конкретная задача сохраняет приоритет, а подбор продолжения учитывает уровень и предпочитаемый формат из сохранённого профиля. Одиночный несвязанный клик не вытесняет подтверждённую пару. Повторы по одной карточке и открытие превью порог не повышают. При первом переходе без прежней истории и без заданной темы используются сходство с открытой карточкой и известные экспертные связи, включая общих соседей. Третий слот по возможности предлагает другой формат и смежную тему. Вес событий по времени снижается вдвое за 28 дней.
4. **Дедупликация топ-3 и баланс доступа:** в первых трёх позициях исключаются почти одинаковые карточки одной роли (две теории или два инструмента — остаётся более подходящая по формату), но связка «объяснение темы + инструмент (шаблон/калькулятор)» сохраняется вместе. Новые показы на реальном каталоге записываются под отдельной версией алгоритма для сравнения CTR.

Отчёт за всё время считает долю показов с переходом по алгоритмам и позициям. Он исключает тестовый аккаунт и учитывает до одного перехода на показ. Локально из корня проекта:

```powershell
python -X utf8 -m app.ctr_report
```

В каталоге действующего Docker Compose запускайте отчёт внутри контейнера, чтобы прочитать его SQLite:

```sh
docker compose exec -T web python -X utf8 -m app.ctr_report
```

Веб-отчёт и управление админ-аккаунтами доступны после отдельного входа на `/admin/login`. Администратор может создать новый аккаунт или выдать роль существующему по логину. Для первого администратора и сброса пароля используйте команды из каталога Docker Compose:

```sh
docker compose exec web flask --app app.ui.web:create_app admin grant ЛОГИН
docker compose exec web flask --app app.ui.web:create_app admin reset-password ЛОГИН
```

Смена пароля требует сохранённую почту, текущий пароль и одноразовый код. Запрос кода принимает `POST /profile/password/request-code`, подтверждение принимает `POST /profile/password`. Код привязан к сеансу и действует 10 минут. После подтверждения предыдущие сессии завершаются. Минимальная длина пароля — 8 символов.

Демо показывает код `000000` в интерфейсе. Для отправки реальных писем передайте адаптер `send_password_code(email, code)` в фабрику `create_app(password_code_sender=send_password_code)`. В этом режиме приложение генерирует случайный код и передаёт его адаптеру. Адаптер сообщает об ошибке отправки исключением.

Ссылка «Забыли пароль?» открывает `/forgot-password`. Без почтового отправителя форма показывает демонстрационный сценарий с кодом `000 000`, который сохраняет прежние пароли аккаунтов. С подключённым отправителем приложение высылает на сохранённую почту одноразовый код на 10 минут. Форма `/reset-password` принимает код и новый пароль, после сброса прежние сеансы завершаются. Для подключения API почтового сервиса используйте тот же адаптер `password_code_sender` в `create_app`.

В Docker Compose почтовый отправитель настраивается в серверном `.env` через `ALFA_SMTP_HOST`, `ALFA_SMTP_PORT` и `ALFA_SMTP_FROM`. Для сервера с авторизацией добавьте `ALFA_SMTP_USER` и `ALFA_SMTP_PASSWORD`. На порту 465 используется TLS с начала соединения, на остальных портах используется STARTTLS. Эта настройка включает доставку кодов и при смене пароля из профиля.

Поиск по реальному каталогу по умолчанию включает бесплатные, платные и подписочные карточки. Пользователь может сузить поиск чекбоксами. Карточки сохраняют ссылки на Альфа-Курс, где действуют условия доступа к обучению. Для персонализированного чата и траектории обучения учитывается Курс+. Выдать или отозвать это право в демо можно командами ниже. Для тестового профиля используется логин `demo`.

Кнопка в профиле вызывает `POST /profile/course-plus/activate`. В демо она показывает уведомление. Для подключения сервиса передайте в `create_app` адаптер `course_plus_activator(account_id)`. Адаптер возвращает `True` только после подтверждения права на подписку внешним сервисом. Тогда приложение сохраняет доступ в базе.

```bash
docker compose exec web flask --app app.ui.web:create_app admin course-plus ЛОГИН
docker compose exec web flask --app app.ui.web:create_app admin course-plus ЛОГИН --revoke
```

- `/admin` показывает основные показатели и краткие оценки сохранённых офлайн-прогонов. Рабочие пороги заданы в `app/ui/admin_summary.py`.
- `/admin/tests` показывает последние серверные офлайн-отчёты и время прогонов по МСК. Сайт читает сохранённые файлы, расчёт выполняется через CLI.
- `/admin/experiments` управляет живым A/B-тестом. Администратор выбирает два алгоритма, долю A среди участников и долю всего трафика. Каждый запуск хранится отдельно. Для смены настроек завершите предыдущий запуск.
- `/admin/analytics` показывает дневную динамику, разбивку по позициям и топ карточек с фильтром по формату.
- `/admin/settings` содержит управление ролями и очистку истории текущего администратора. Записи показов для CTR сохраняются.
- `/admin/roadmap` описывает варианты развития стека и возможный порядок подключения ClickHouse.

Будущий источник live-данных подключается через `create_app(live_data_provider=provider)`. Вызов `GET /admin/api/v1/live-data?days=30` требует отдельного входа в админку и принимает интервал от 1 до 90 дней. Без адаптера ответ — HTTP 503 со статусом `not_configured`. Адаптер принимает включительные границы UTC как `date` и возвращает `LiveDataSnapshot(source, as_of, daily)`. `as_of` содержит часовой пояс. `daily` — пары даты и `DailyActivity(impressions, clicks, attributed_clicks)`. API выводит только агрегаты. `clicks` группируется по дате перехода, `attributed_clicks` — по дате исходного показа, на который атрибутирован переход. `ctr_pct` считается как `100 × attributed_clicks / impressions` и равен `null` в дни без показов.

В эксперименте назначение гостя хранится в подписанной cookie, а при регистрации переносится в аккаунт. Эксперимент охватывает алгоритм каталога и чата. Статьи и подкасты над формой общие для двух групп. В отчёт входят показы блока общей выдачи, переходы, открытия описания и возврат на 7-й календарный день после первого показа (UTC). Общее число назначений выводится отдельно от числа участников с подтверждёнными показами. Оплата, заявки и глубина чтения на Альфа-Курсе требуют событий от внешней платформы.

Обложки из публичного каталога «Альфа-Курса» сопоставлены с ID материалов в `app/ui/public-covers.json`. Если у карточки нет доступной обложки, отображается цветная иллюстрация.

Данные исходного тестового сценария `app.ui.stub.recommend` хранятся в отдельном архиве админ-панели и исключаются из текущего отчёта, графиков и рейтинга карточек.

Консольное демо работает на стандартной библиотеке. Для тестов используйте окружение с зависимостями веб-демо.

```powershell
python -X utf8 -m app
python -X utf8 -m app --goal "продвижение бизнеса" --history fixtures/history.demo.json
.\.venv\Scripts\python.exe -X utf8 -m unittest discover -s tests -v
```

Первый запуск использует пустой профиль и пустую историю. Второй передаёт задачу и тестовые события. Алгоритм учитывает события с ID, которые присутствуют в загруженном каталоге.

## Структура

| Путь | Содержимое |
| --- | --- |
| `app/contracts.py` | Типы каталога, профиля, истории и результата `recommend`. |
| `app/catalog/` | Нормализация бэкапа (`search_text`, `recent_popularity_score`) и загрузка каталога, связей, подписок и дат. |
| `app/recommender/` | Ранжирование (`engine.py`, `hybrid.py`), ежедневные подборки (`daily.py`) и блок «Следующий курс» (`next_courses.py`). |
| `app/ui/`, `app/__main__.py` | Веб-интерфейс (постраничная выдача, чат, профиль, `/admin`) и консольный запуск подбора. |
| `evaluation/` | Бейзлайн, размеченные профили, стресс-сценарии и офлайн-оценка качества. |
| `fixtures/` | Семь синтетических материалов и журнал из трёх действий. Ссылки на `example.com` служат примерами. |
| `tests/` | Автотесты контрактов, рекомендателя, чата, оценок и веб-маршрутов. |

Выгрузку организаторов храните локально в `data/`, который исключён из Git. Офлайн-сравнение в `evaluation/` использует размеченные фикстуры из репозитория.
